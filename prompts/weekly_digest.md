# 주간 글 작성 지시문 (Claude Code 가 매주 따라 할 것)

> 사용법: Claude Code 에게 **"prompts/weekly_digest.md 대로 이번 주 글 써줘"** 라고 말한다.
> 5단계 이후에는 예약 작업이 매주 월요일에 이 문장을 자동으로 보낸다.

## 독자와 목적
- 독자: 반도체 공정·장비 직무 취업을 준비하는 대학원생 (본인). CNT 냉음극 멀티빔 전자원을 연구한다.
- 목적: 이번 주 공정 기술 흐름을 **면접에서 설명할 수 있을 만큼** 이해하는 것. 뉴스 요약 모음이 아니다.

## 순서
1. (5단계 이후) `git pull` 로 GitHub Actions 가 모은 최신 데이터를 받는다.
2. 입력 만들기: `.venv\Scripts\python collector\week_input.py` → `data/weekly/<주차>_input.md`
   + 태그 통계 그림 `site/content/posts/<주차>/tags.svg` 가 자동 생성된다.
   이미 같은 주차 글(`site/content/posts/<주차>/index.md`)이 있으면 멈추고 사용자에게 알린다.
3. 입력 파일만 읽고 **핵심 기술 3개**를 고른다. 기준:
   - 실적·인사·행사·주가 기사보다 **공정·장비·소재 기술** 내용이 있는 것
   - 서로 다른 공정 분야에서 고르기 (예: 패키징 하나, 노광 하나, 메모리 하나)
   - 뉴스 여러 건이 같은 흐름을 가리키면 묶어서 하나로
4. 고른 3개의 원문만 열어 읽는다 (최대 6개 링크). 나머지는 입력 파일의 요약만 쓴다.
   - `news.google.com` 링크는 원문이 열리지 않는다(2026-W47 확인). 이런 글은 핵심 근거로 삼지 말고
     보조 출처로만 쓰며 "원문 미확인"을 붙인다. 핵심 근거는 디일렉·SemiEngineering·arXiv 등 직접 링크로.
5. 그림을 준비한다 (아래 "그림 규칙").
6. 아래 형식으로 `site/content/posts/<주차>/index.md` 를 쓴다 (글 폴더 = 그림과 글을 한 폴더에).
7. `cd site; hugo --quiet` 로 빌드 오류가 없는지 확인한다.
8. 사용자에게 무엇을 골랐는지 3줄로 보고하고, "내 코멘트" 칸을 채워달라고 말한다.
9. (5단계 이후) 커밋하고 push 한다. 커밋 메시지: `post: <주차> 주간 정리`

## 배경 지식 규칙
- 핵심 기술마다 **배경 지식 상자**(`>` 인용문, 첫 줄 `> **배경 지식 — 주제**`)를 1~3개 넣는다.
  공정 엔지니어 면접 수준: 기본 구조·원리, 공정 순서, 대표 불량, 관련 공정과의 연결, 업계 선례.
- 배경 지식은 교과서·업계 일반 지식만. 수치는 널리 알려진 값(파장, NA 등)만 쓰고, 애매하면 "수십 µm", "수백 °C 이하"처럼 범위로.
- 기사 내용(상자 밖)과 배경 지식(상자 안)을 섞지 않는다. 상자 밖에서 배경을 말할 땐 "(배경)"을 붙인다.
- 굵게 표시 주의: `**…(괄호)**다` 처럼 닫는 `**` 앞이 괄호·마침표이고 바로 뒤가 한글이면 굵게가 깨진다.
  `**가상계측**(VM)은` 처럼 괄호를 `**` 밖으로 뺀다. `A*STAR` 같은 별표는 `A\*STAR` 로.
- 글 끝에 **용어 정리** 표를 둔다. 면접 질문은 `<details>` 로 접어 답변 뼈대를 숨긴다.

## 그림 규칙
- 핵심 기술마다 그림 1개 이상. 넣는 법: `{{</* fig src="파일" caption="설명" source="출처" source_url="…" license="…" license_url="…" */>}}`
  그림 번호는 자동. 본문에서 "그림 N" 으로 가리킬 땐 순서를 확인한다. 사진은 `class="narrow"`.
- 사용자 방침: **가능하면 원본 그림을 쓰고, 안 되면 개념도.** 원본은 아래 순서로 찾는다.
  1. **자유 라이선스 원본** — Wikimedia Commons(CC BY, CC BY-SA, CC0, Public domain),
     CC BY 계열 오픈액세스 논문 그림(arXiv 는 논문마다 라이선스 확인: abs 페이지의 License 링크).
     Commons 는 요청이 잦으면 429 로 막으니 요청 사이에 쉬고, 막히면 건너뛴다.
  2. **기업 뉴스룸 보도자료 이미지** (삼성전자·SK하이닉스 뉴스룸 등) — 그 뉴스룸의 이용 조건이 인용·재게시를 허용할 때만.
     허용 여부를 확인하지 못하면 쓰지 않는다.
  3. 위에서 못 구하면 **직접 그린 개념도 (SVG)** — 단면도, 공정 흐름, 비교 그림. 흰 배경, 한글 글꼴(`Malgun Gothic, Apple SD Gothic Neo, Noto Sans KR`),
     폭 820~880, `width`/`height` 속성 포함. source="직접 작성 (…기반)".
- 원본을 쓸 때는 작가·라이선스·원본 페이지를 글 폴더의 `figures_sources.json` 에 기록하고 캡션에 표기한다.
- **언론사 기사 사진·그래픽은 출처를 달아도 가져오지 않는다.** 비상업이어도 무단 게시는 저작권 침해가 될 수 있다.
  필요하면 기사 내용을 바탕으로 개념도를 다시 그리고, 캡션에 "○○ 기사 내용 기반" 과 링크를 단다.
- 목록 썸네일: front matter 에 `cover: <대표 그림 파일명>`.

## 사실 확인 규칙 (중요)
- 기사·논문에 **나온 사실**과 **일반 배경 지식**을 구분한다. 배경 설명에는 문장 앞에 "(배경)"을 붙인다.
- 수치(나노, 적층 수, 금액, 일정)는 원문에 있는 것만 쓴다. 기억으로 수치를 만들지 않는다.
- 원문 문장을 옮겨 쓰지 않는다. 내 말로 요약하고 반드시 원문 링크를 단다. 인용은 꼭 필요할 때만 15단어 이내 1개.
- 원문이 열리지 않으면 "원문 미확인"이라고 쓰고 입력 요약 범위 안에서만 쓴다.

title: "<주차> 반도체 공정 주간 정리 — <이번 주 키워드 2~3개>"
date: <작성일 YYYY-MM-DD>
tags: [<핵심 기술에 해당하는 공정 태그들>]
summary: "<한 문장 요약>"
cover: <대표 그림 파일명>

**원리** — 이 공정/기술이 어떻게 동작하는지. 공정 순서나 물리 원리 중심으로 3~5문장.

**왜 중요한가 (기존 대비)** — 무엇을 대체·개선하는지.

**남은 난제** — 수율, 장비, 소재, 비용 측면 2~3개 항목.

**관련 기업·장비** — 원문에 나온 것만.

   - 답변 뼈대: <3~4개 키워드 흐름>
2. …

## 내 연구와의 연결
CNT 냉음극 멀티빔 전자원 연구와 이번 주 기술의 접점을 2~4문장.
접점 후보: 전자빔 검사·계측(멀티빔 SEM), 멀티빔 마스크 라이터, 진공·플라즈마 공정, 전계방출 소자, 박막 증착·CNT 성장.
억지 연결이면 쓰지 말고 "이번 주는 직접 접점 없음"이라고 쓴다.
